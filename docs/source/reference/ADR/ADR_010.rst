==============================================================
ADR-010: Migrating to Official LinkML Toolchain for SDK Generation
==============================================================

**Status**: **`Accepted`**

📋 Context
-----------
Previously, EarlySign utilized TypeSpec for defining its statistical protocol schemas (ES3). While TypeSpec excelled at API definitions, it proved less ideal for describing general data structures and complex sequential procedures required by the event-sourced ledger architecture.

To improve schema maintainability and type-safety, the project transitioned to LinkML. During the initial stabilization phase, a custom, ad-hoc Python generator (`RobustEarlySignGenerator`) was developed to handle cross-schema module imports and specific Pydantic v2 naming conventions (e.g., `_Base` suffixing for shadowed core classes).

However, maintaining a custom 400-line generator introduces long-term maintenance debt and deviates from the project's preference for using standard, well-supported tools.

💡 Decision
------------
We will decommission the custom `RobustEarlySignGenerator` and migrate the SDK generation pipeline to the official LinkML `gen-pydantic` toolchain.

Key technical decisions in this migration:
1.  **Modular Generation**: Use `gen-pydantic --no-mergeimports` to maintain separate Python modules for `Base`, `Binomial`, `Continuous`, and method-specific schemas.
2.  **Explicit Import Mapping**: Utilize an `importmap.yaml` to map LinkML schema IDs (e.g., `https://earlysign.io/schema/ES3/base`) to their definitive Python modules (e.g., `earlysign.schema.ES3.Base`).
3.  **Standardized Specifications**: Refactor `schema.yaml` files to use LinkML-idiomatic patterns for dictionary defaults (e.g., `multivalued` with `inlined` slots) instead of the previous `ifabsent: "{}"` ad-hoc hack.
4.  **CLI Integration**: The `earlysign-schema-gen` CLI tool will act as a thin wrapper around these standard LinkML commands.

✨ Consequences
-----------------
**Positive:**
*   Reduced maintenance burden by removing ~400 lines of custom ad-hoc codegen logic.
*   Improved interoperability with the wider LinkML ecosystem.
*   Clearer mapping between schema definitions and generated Python code through standard configuration.

**Negative:**
*   Requires a one-time refactoring of existing `schema.yaml` files to match official generator expectations.
*   Slightly less direct control over the exact formatting of generated classes compared to the custom generator.
